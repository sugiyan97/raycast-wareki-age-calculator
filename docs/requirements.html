01

概要・目的

和暦と西暦の相互変換をRaycastの検索バーから即座に行える既存OSS拡張機能をベースに、年齢計算機能を追加する。「昭和58年は西暦何年か」「1983年生まれは今何歳か」といった日常的な変換・計算を、ブラウザ検索を挟まずローカルで完結させることが目的。

02

スコープ

対象

  • 和暦⇔西暦変換（既存仕様を踏襲）
  • 年齢計算機能の新規追加
  • 身内少人数への非公開配布

対象外

  • Raycastストアへの公開
  • 多言語対応（日本語UIのみ）
  • 旧暦・干支・皇紀など他の暦法
  • 明治より前の元号、改元日の厳密な月日判定
03

前提・制約

  • Node.js + Raycast API（React / TypeScript）で実装する。
  • 外部API通信は一切行わない。完全オフライン・ローカル完結（プライバシー面で安全）。
  • 依存パッケージは @raycast/api のみを維持し、原則追加しない。
  • 配布は本人＋身内少人数のみ。ストア審査要件は考慮不要。
04

機能要件

既存踏襲4.1　和暦⇔西暦変換

  • コマンド1つ（mode: "view"）、List UIで検索バー入力に対しリアルタイムに変換候補を表示。
  • 入力が数値のみ → 西暦。元号プレフィクス（令和1 令1 R1 等）＋数字 → 和暦。
  • 入力1つに対し、西暦1つ＋5元号すべての換算結果を一括リスト表示（既存設計を維持）。開始年より前の組み合わせは除外。
  • 「元年」表記は非対応（令和1年のまま）。既存仕様どおり据え置く。
  • アクションは Copy to Clipboard のみ。

新規4.2　年齢計算

生年（西暦 or 和暦）を入力すると、変換結果リストに満年齢を追加表示する。詳細仕様は §10 で確定済み。

  • 入力 — 年のみ（1983 S58）は「誕生日前なら42歳／後なら43歳」の幅表示。生年月日（1983/4/1 19830401 S58.4.1）は確定表示。
  • 計算 — 満年齢のみ（数え年は対象外）。基準日は実行時のローカル日付。誕生日当日に加齢済みとみなす。2/29生まれは平年3/1加齢。
  • 例外 — 未来の生年月日はエラーにせず、「あと◯年後に誕生」の形式で表示する。

4.3　UI/UX要件

コマンド構成の選択肢は次の2案。

推奨案 A
既存コマンドに統合

変換結果リストの末尾に年齢行を追加。入力は「年」で共通のため、1回の入力で全情報が見えるUXが既存設計思想と一致。実装も最小。

案 B　コマンド分離

「年齢計算」コマンドを別途追加。生年月日入力用の専用UIを作りやすいが、コマンド切替の手間が増える。

06

非機能要件

  • 完全オフライン動作。ネットワーク権限・外部通信コードを含めない。
  • 入力ごとの表示更新は体感即時（単純計算のみなので自然に満たされる）。
  • 依存は @raycast/api（＋開発時のTypeScript／ESLint）のみ。日付ライブラリは導入しない。
  • コード規模は src/index.tsx 1ファイル中心を維持し、肥大化する場合のみ計算ロジックを分離する程度に留める。
07

技術要件

  • 言語 — TypeScript（React、Raycast List UI）
  • 依存 — @raycast/api（ベースのバージョンを起点に必要なら更新）
  • Node.js — Raycast推奨のLTS（v20系以上目安）
  • 実装方針 — 既存の正規表現パース＋開始年テーブル方式を踏襲し、日付形式のパースを追加。年齢計算は Date 標準APIのみで実装。既存の変換ロジックには手を入れず、追加関数として実装（デグレ防止）。
08

配布・共有要件

  • Raycastストアには公開しない。
  • 配布方法 — 非公開GitHubリポジトリ経由、または Zip 手渡し。
  • 受け取り側は Raycast の Add Local Extension（Import Extension）でローカル読み込み。
  • 対象は身内少人数のみ。日本語READMEにインストール手順を1ページで記載する。
09

受け入れ基準・テスト観点

  • 既存の和暦⇔西暦変換がベースリポジトリと同一の結果を返す（デグレなし）
  • 元号切り替わり年の境界値 — 1989→昭和64年/平成1年、2019→平成31年/令和1年、1912、1926、1868
  • 各元号の開始年より前の換算が表示されない（例：1980に令和換算が出ない）
  • 年齢 — 基準日2026-08-21で 1983/4/1→43歳、1983/12/1→42歳（誕生日前）、誕生日当日は加齢済み
  • 閏日 2000/2/29 が正しくパース・計算される
  • 未来日付・0以下の年・不正文字列でクラッシュせず、空リスト or 妥当な表示になる
  • Copy to Clipboard が全行で機能する
  • npm run build が警告なく通り、Add Local Extension で動作する
10

確定仕様

2026-08-21、ユーザー確認済み。全項目が確定し、実装着手可能な状態。

  1. 年齢は満年齢のみ。数え年は併記しない。
  2. 入力は生年・生年月日の両対応。年のみ入力は幅表示。
  3. 年のみ入力時は幅表示（例：42〜43歳）。
  4. 誕生日当日に加齢済みとする（前日満了方式は採らない）。
  5. 2/29生まれの平年の加齢日は3/1。
  6. 未来の生年入力時は「あと◯年後に誕生」と表示する。
  7. 既存の令和1年表記は変更しない（元年表記は導入しない）。
  8. 逆引き（年齢→生年検索）は初版では対象外。
11
