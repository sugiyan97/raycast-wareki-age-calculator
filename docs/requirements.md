## 1. 概要・目的

和暦と西暦の相互変換をRaycastの検索バーから即座に行える既存OSS拡張機能をベースに、**年齢計算機能を追加**する。

「昭和58年は西暦何年か」「1983年生まれは今何歳か」といった日常的な変換・計算を、ブラウザ検索を挟まずローカルで完結させることが目的。

---

## 2. スコープ

### 2.1 対象

- 和暦⇔西暦変換（ベースリポジトリの既存仕様を踏襲）
- 年齢計算機能の新規追加
- 身内少人数への非公開配布（Zip / 非公開GitHubリポジトリ）

### 2.2 対象外

- Raycastストアへの公開
- 多言語対応（日本語UIのみ。英語入力は元号ローマ字略称の範囲でのみ対応）
- 和暦以外の暦法（旧暦・干支・皇紀等）
- 明治より前の元号
- 日付単位の和暦変換（改元日をまたぐ月日の厳密判定は行わず「年」単位で扱う。月日を考慮するのは年齢計算のみ）

- 依存パッケージは `@raycast/api` のみを維持し、原則追加しない。
- 配布は本人＋身内少人数のみ。ストア審査要件（アイコン品質、README英語化等）は考慮不要。

## 4. 機能要件

### 4.1 既存機能: 和暦⇔西暦変換（ベース仕様を踏襲、変更なし）

- コマンド1つ（`mode: "view"`）、List UIで検索バー入力に対しリアルタイムに変換候補を表示する。
- 対応元号と開始年:

  | 元号 | 開始年（西暦） |
  |---|---|
  | 令和 | 2019 |
  | 平成 | 1989 |
  | 昭和 | 1926 |
  | 大正 | 1912 |
  | 明治 | 1868 |

- 入力解釈:
  - 数値のみ → 西暦として扱う
  - 元号プレフィクス（漢字フル・漢字1文字・ローマ字1文字。例: `令和1` / `令1` / `R1`）＋数字 → 和暦として扱う
- 出力: 入力1つに対し、西暦1つ＋5元号すべての換算結果を一括リスト表示（既存設計を維持）。元号開始年より前になる組み合わせは除外する。
- 「元年」表記は非対応（入出力とも `令和1年` 形式）。既存仕様のまま据え置く（**変更しないことが確定**）。
- アクションは Copy to Clipboard のみ。

### 4.2 新規機能: 年齢計算（確定仕様）

生年（西暦 or 和暦）を入力すると、変換結果リストに「満年齢」を追加表示する。

#### 入力パターン

| パターン | 入力例 | 挙動 |
|---|---|---|
| 年のみ | `1983` / `S58` | 幅表示（例: 「誕生日前なら42歳／後なら43歳」）＊**確定: 幅表示を採用** |
| 生年月日 | `1983/4/1` / `19830401` / `S58.4.1` 等 | 基準日時点の満年齢を1つに確定して表示 |

#### 計算ロジック

- **満年齢のみ**採用。数え年は併記しない（確定）。
- 基準日は実行時のローカル日付（`new Date()`）。
- **誕生日当日は加齢済み**とする（確定。法律上の「誕生日前日満了」方式は採らない）。
- **2/29生まれは平年では3/1に加齢**とみなす（確定）。
- 未来の生年月日はエラー扱いにせず、**「あと◯年後に誕生」**の形式で表示する（確定）。

#### 出力形式

Listの1行として追加し、Copy to Clipboard で年齢の数値をコピー可能とする。

- `1983年（昭和58年）生まれ → 満43歳（誕生日前なら42歳）`（年のみ入力時）
- `1983年4月1日生まれ → 満43歳`（生年月日入力時）
- `2030年生まれ → あと4年後に誕生`（未来の生年入力時）

### 4.3 UI/UX要件（確定: 案A採用）

**既存コマンド1つに統合する。** 変換結果リストの末尾に年齢行を追加する。

採用理由: 入力が同じ「年」であり、1回の入力で全情報が見えるUXが既存設計思想と一致し、実装も最小で済むため。

不採用案: 「年齢計算」コマンドを別途追加する案Bは、コマンド切替の手間が増えるため見送り。

## 5. 入出力仕様（例）

基準日: 2026-08-21（令和8年）

| 入力 | 解釈 | 出力例（リスト表示） |
|---|---|---|
| `2019` | 西暦 | `令和1年` `平成31年` `昭和94年` `大正108年` `明治152年` ＋ `満7歳（誕生日前なら6歳）` |
| `R8` / `令8` / `令和8` | 和暦 | `西暦2026年` ＋ 他元号換算 ＋ `満0歳` |
| `S58` | 和暦 | `西暦1983年` ＋ 他元号換算 ＋ `満43歳（誕生日前なら42歳）` |
| `1983/4/1` | 生年月日 | `昭和58年4月1日` ＋ `満43歳` |
| `2000/2/29` | 生年月日（閏日） | `平成12年2月29日` ＋ `満26歳` |
| `2030` | 未来の西暦 | 和暦換算 ＋ `あと4年後に誕生` |
| `abc` / `令和` のみ | 不正入力 | 候補なし（空リスト、エラーは出さない） |

## 6. 非機能要件

- 完全オフライン動作。ネットワーク権限・外部通信コードを含めない。
- 入力ごとの表示更新は体感即時（数ms〜数十ms。単純計算のみなので自然に満たされる）。
- 依存は `@raycast/api`（＋開発時の TypeScript / ESLint）のみ。日付ライブラリ（date-fns等）は導入しない。
- コード規模は `src/index.tsx` 1ファイル中心を維持し、肥大化する場合のみ計算ロジックを1ファイル分離する程度に留める。

---

## 7. 技術要件

- **言語**: TypeScript（React、Raycast List UI）
- **依存**: `@raycast/api`（ベースのバージョンを起点に必要なら更新）
- **Node.js**: Raycast推奨のLTS（v20系以上目安）
- **実装方針**:
  - 既存の正規表現パース＋開始年テーブル方式を踏襲し、日付形式（`YYYY/M/D` / `YYYYMMDD` / `G##.M.D` 等）のパースを追加する
  - 年齢計算は `Date` 標準APIのみで実装（(基準日 − 生年月日) の年差＋誕生日到来判定）
  - 既存の変換ロジックには手を入れず、追加関数として実装（デグレ防止）

## 9. 受け入れ基準・テスト観点

- [ ] 既存の和暦⇔西暦変換がベースリポジトリと同一の結果を返す（デグレなし）
- [ ] 元号切り替わり年の境界値: `1989`→昭和64年/平成1年の両方が表示される、`2019`→平成31年/令和1年、`1912`、`1926`、`1868`
- [ ] 各元号の開始年より前の換算が表示されない（例: `1980` に令和換算が出ない）
- [ ] 年齢: 基準日2026-08-21で `1983/4/1`→43歳、`1983/12/1`→42歳（誕生日前）、誕生日当日→加齢済み
- [ ] 閏日 `2000/2/29` が正しくパース・計算される（平年の加齢日仕様どおり）
- [ ] 未来日付・0以下の年・不正文字列でクラッシュせず、空リスト or 妥当な表示になる
- [ ] Copy to Clipboard が全行で機能する
- [ ] `npm run build` が警告なく通り、Add Local Extension で動作する

## 10. 確定仕様一覧（旧オープンクエスチョン、全項目確定済み）
